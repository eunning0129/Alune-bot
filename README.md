# 알룬 · 여 운 닉네임 등록 봇

## 디스코드 설정

1. Developer Portal에서 앱과 봇을 만들고 **Server Members Intent**를 활성화합니다.
2. OAuth2에서 `bot`, `applications.commands` 범위로 초대합니다. 알룬에게 **역할 관리**, **닉네임 관리**, **멤버 추방**과 대상 채널에서 **채널 보기**, **메시지 보내기**, **임베드 링크** 권한을 부여합니다.
3. 알룬의 서버 역할을 관리 대상 역할 및 닉네임 변경·자동 추방 대상 멤버보다 위에 놓습니다.
4. 자기소개와 서버·내전 규칙 채널은 미인증 멤버가 읽을 수 있게 합니다. 입퇴장 기록 채널에서는 `@everyone`의 채널 보기를 차단하고, 관리자와 알룬에만 채널 보기를 허용합니다. 알룬의 채널 접근을 별도로 허용할 경우 알룬 멤버를 직접 추가합니다.
5. `미인증`, `규칙확인완료`, `내전` 역할과 각 승인 담당자 이름의 표시용 역할을 만듭니다. 표시용 역할은 서버 권한과 채널 허용 권한을 모두 비워 둡니다. 내전 채널 접근은 `내전` 역할에 설정합니다.
6. Discord 개발자 모드에서 서버·채널·멤버·역할 ID를 복사합니다. `.env.example`의 항목을 실제 값으로 채웁니다. `APPROVER_ROLE_MAP`은 예를 들어 `{"123456789012345678":"987654321098765432"}`처럼 관리자·보조관리자의 유저 ID를 각 담당자의 이름 역할 ID에 연결하는 JSON입니다.

## Railway에서 실행

- 이 폴더의 파일을 저장소 루트에 올린 뒤 Railway 서비스로 연결합니다. Dockerfile로 빌드됩니다.
- `.env.example`의 변수들을 Railway Variables에 등록합니다. 실제 토큰은 저장소에 올리지 않습니다.
- 서비스에 Volume을 `/data`에 마운트하고 `DB_PATH=/data/alune.sqlite3`로 설정합니다. 복제본은 1개로 실행합니다.
- 로그에 `Connected as`가 나오면 서버에서 관리자로 `/닉네임등록`, `/규칙확인`을 각각 한 번 실행합니다. 규칙 확인 패널 위에 실제 규칙 글을 게시해 두세요.

로컬에서는 Python 3.11 이상에서 `python -m pip install -r requirements.txt`로 설치하고, 예제 변수를 셸 환경에 등록한 뒤 `python bot.py`를 실행합니다. Docker를 사용한다면 `.env.example`을 `.env`로 복사해 값을 채운 뒤 아래 명령을 실행합니다.

```sh
docker build -t alune .
docker run --rm --env-file .env -v alune-data:/data -e DB_PATH=/data/alune.sqlite3 alune
```

## 승인과 입퇴장 처리

- 새 멤버에게 미인증 역할을 지급합니다. 신청을 수락하면 서버 닉네임을 변경하고 수락한 담당자 이름의 역할을 지급합니다. 승인할 때마다 등록 패널을 새로 게시하고 이전 패널을 정리합니다.
- 신청자가 등록 패널의 **내 신청 상태**를 누르면 승인 결과와 규칙 채널 링크를 본인만 볼 수 있습니다. 알룬은 승인 DM을 보내지 않습니다.
- 승인된 멤버가 규칙 채널에서 확인 버튼을 누르면 규칙확인완료·내전 역할이 지급되고 미인증 역할이 제거됩니다.
- 신청 임베드와 FOW 전적 링크는 신청서를 제출한 자기소개 채널에 표시됩니다. 이 채널을 볼 수 있는 멤버는 제출 내용을 볼 수 있고, 탑레를 확인한 뒤 서버 관리자와 `보조관리자` 역할 보유자가 수락할 수 있습니다. 거절은 서버 관리자 권한이 필요합니다.
- 입장과 퇴장 횟수는 따로 누적합니다. **퇴장 3회 이상인 유저가 다시 들어오는 순간** 자동 추방하고 별도 임베드를 기록합니다. 알룬의 자동 추방 자체는 퇴장 횟수에 더하지 않습니다. Discord가 보내는 다른 퇴장 이벤트(수동 추방 등)는 퇴장 횟수에 포함됩니다. 집계는 봇이 실행되는 동안 관측한 이벤트를 기준으로 합니다.
- 패널이 삭제됐거나 자동 재게시가 실패하면, 봇이 온라인일 때 관리자가 `/닉네임등록`으로 복구할 수 있습니다. 규칙 확인 패널은 `/규칙확인`으로 복구합니다. SQLite를 보존하면 재시작 후에도 마지막 패널 버튼, 신청 상태, 입퇴장 횟수가 이어집니다.

- 라인은 `TOP MID`처럼 띄어쓰기로 구분합니다. 올라이너는 `ALL`만 입력합니다. 정글은 `JUG`로 입력해도 `JG`로 표시됩니다. 예: `닉#KR1/P1/TOP MID`.

## 초대 경로 및 별빛지기 뉴비 역할 처리

- 닉네임 신청 창에서 `없음`, `홍보사이트`, `듀오지지`, `서버 멤버 초대`를 선택합니다. 서버 멤버 초대는 초대한 멤버도 선택해야 합니다. 자기소개 채널의 신청 임베드에 해당 멤버가 @멘션으로 표시되며 알림은 보내지 않습니다.
- 재배포 후 관리자가 `/닉네임등록`을 한 번 실행하면 기존 등록 안내의 작성 양식에도 초대 경로가 표시됩니다. 기존 신청 기록은 유지됩니다.
- 두 봇을 같은 서버에서 실행합니다. 뉴비 역할을 가진 유저의 결과를 별빛지기에서 기록하면 별빛지기가 누적 전적(승+패)을 확인해 3판 이상인 경우 `뉴비` 역할을 회수합니다. 별빛지기에 역할 관리 권한을 주고 별빛지기 역할을 `뉴비`보다 위에 배치하세요.
- 별빛지기는 저장된 결과 한 건을 1판으로 집계합니다. 3판 2선제의 개별 세트 및 전적 없이 종료한 내전은 따로 집계하지 않습니다. 이미 3판 이상인 뉴비 멤버는 별빛지기의 `/뉴비정리`로 정리할 수 있습니다.
